# FPGA 照片接收器

## 当前状态

电脑程序已实现，并通过模拟FPGA回环、丢包重试、重复包处理、贴图还原和PNG生成测试。它需要配套的新网口FPGA版本；当前桌面主工程仍保留原来可用版本，不能用旧bit直接收照片。用户已决定自行完成整机编译。最近候选完成布局，Slice为21189/21216（99.87%）、ERAM87/108、DSP33/40；路由优化已按用户要求停止，最终时序尚未通过验收。之后将PHY转发时钟改为持续输出，移除跨90°相位的复位路径；该小改动尚未重新做整机编译，因此布局资源仅作此前候选参考。尚未进行网线实机测试。

## 电脑怎样接收

1. 用网线连接FPGA板载网口与电脑有线网口。当前首版为**千兆全双工链路**，电脑网卡或USB网卡应支持1Gbps；系统中的以太网连接速度应显示1.0Gbps。百兆链路尚未实现，不能直接当作百兆兼容版使用。
2. 将电脑有线网卡IPv4设为 `192.168.137.1`，子网掩码 `255.255.255.0`，网关和DNS留空。FPGA固定地址为 `192.168.137.2`。若电脑其他网卡正使用相同网段，应先调整网络，避免冲突；本程序不会自行修改系统网络设置。
3. 安装含Tkinter的Python 3。程序只用标准库，不需要安装Pillow、NumPy或网口调试助手。
4. 保持本目录的 `photo_receiver.py` 和 `photo_assets.json` 在一起，双击 `启动照片接收器.bat`，点击“开始接收”。Windows防火墙若询问权限，应允许该Python程序在此次使用的网络接收数据；不要整体关闭防火墙。
5. FPGA先拍一张照片。暂定在非曝光按键模式下，**长按KEY4约0.8秒**触发发送；KEY4短按松开后仍执行原来的相册查看/返回操作。没有照片不会触发导出。
6. 窗口显示接收进度，缺包自动重试。接收完成后生成PNG及一份传输信息JSON，默认位于 `received_photos` 文件夹，可点击“打开照片文件夹”。
7. 照片导出期间暂停接受新的拍照请求，避免正在发送的照片被替换；原视频和其它控制仍需在最终集成版本上验证。发送中重复长按不叠加任务，网络请求长时间中断后会释放锁定。

## 接收到什么

- 保留1280×720分辨率，不做FPGA端JPEG压缩。
- FPGA发送已保存的滤镜图像及拍摄时贴图参数；电脑按同版素材、像素映射和显示亮度查表还原贴图，然后保存PNG。
- 右上角菜单、亮度文字、检测框、安路Logo等运行叠加不作为照片导出内容。
- 不是完整屏幕录像。素材清单带版本号，接收器资源与FPGA不匹配时拒绝悄悄合成错误贴图。
- 尚需上板比较实际相册画面与电脑保存图片，仿真正确不等于已完成物理网络验证。

## 网络配置

电脑监听UDP 6001，FPGA监听UDP 6002。接收器通过有线网段广播发送短请求，FPGA使用固定IPv4目的地址及以太网广播目的MAC回包，避免在FPGA中加入完整ARP缓存和通用网络协议栈。该精简配置针对电脑与板卡直连或同一二层局域网，不支持跨路由器、DHCP、VLAN和任意IP自动发现。

每个1KiB照片块都携带传输编号和字节偏移。电脑逐块请求、验证长度并重试，按偏移放入图像，全部收齐后才写正式PNG。重试是分块可靠性机制，并不表示已经实现TCP。FPGA以太网帧包含FCS，电脑保存后另记录图像CRC32供本地核对。

## 命令行

```text
python photo_receiver.py --console
python photo_receiver.py --output D:\MyPhotos
```

`--bind` 和 `--target` 可供测试使用；当前FPGA地址和数据报目的地址是固定值，修改电脑参数不会自动改变FPGA地址。

如果提示无法绑定地址，请检查有线网卡IP是否已设为192.168.137.1；端口被占用时，请关闭其他接收器。没有反应时先检查是否使用配套bit、链路是否1Gbps、是否已经拍照和长按发送，以及防火墙权限。

每次重新烧录或重新给FPGA上电后，请关闭并重新启动接收器，使传输编号重新对齐。
